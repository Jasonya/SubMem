# M8: MemSkill adapter

M8 buffers dialogue turns, exports a batch of questions in LongMemEval format,
and runs a MemSkill backend. It returns the backend's final answers through
`MemoryEntry`, with `PARAMETRIC_OUTPUT=True`. The memory factory accepts both
`M8` and its legacy alias `C20`.

## Backend configuration

The MemSkill backend is an external dependency and is not bundled with this
repository. Place a compatible backend at `third_party/MemSkill`, or set
`MemoryConfig.extra["m8_vendor_dir"]` to its directory. Install its dependencies
in the same Python environment as SubMem.

The backend must provide these SubMem integration interfaces:

- `src.controller.LLMController` and `llm_set_context`, wired into the trainer.
- `--controller-backend` and `--controller-llm-model` CLI options.
- Per-query JSON predictions written to `--out-file`.
- Component token usage through `SUBMEM_M8_TOKEN_SIDECAR`.
- Evolved skill loading through `SUBMEM_M8_SKILL_BANK`.

A stock upstream checkout does not provide all of these interfaces.
`scripts/apply_m8_token_patch.sh` adds instrumentation to a backend that already
has the LLM-controller integration. The adapter checks required files and
controller/CLI symbols before launching the backend.

## Usage

Write dialogue turns with `write`, then call `stage_queries` with the complete
question batch before the first `read`. The benchmark runner handles this
staging hook. New writes or staged questions invalidate cached answers.

Each run uses a separate working directory and split file. Backend failures,
timeouts and missing predictions raise errors. Set `M8_UPSTREAM_TIMEOUT` to a
positive number of seconds to override the default eight-hour timeout. Token
usage accumulates across runs until `reset`.

## Tests

```bash
python -m unittest discover -s tests -p 'test_m8_restore.py' -v
```

The offline tests cover registration, ID mapping, batch serialization, output
parsing, cache invalidation, token accounting, reset, concurrent runs and error
handling. They use a deterministic test backend and stub unrelated substrate
imports, so they require no model downloads or API calls. Model execution is
not covered by these tests.
